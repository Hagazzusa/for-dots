시작·중간·끝의 480px/24샘플 draft 세 장과 768px/64샘플 첫 프레임을 실제로 확인했습니다. 다섯 소품이 보이고 눈에 띄는 왜곡·접시 잘림은 없었습니다. 72프레임 모두 hero 메시의 모든 꼭짓점을 투영해 화면 안 여백을 검사했습니다. 계획상 최소 여백은 약 5.33%입니다.

원본과 저장한 애니메이션을 별도로 열어 정적 장면 fingerprint를 비교했습니다. 실제 사용 재질·메시·변환·광원·world가 일치하고, 카메라 외 물체 애니메이션이 없었습니다. Blender가 저장할 때 제거하는 **미사용 기본 재질**은 렌더 장면 fingerprint 대상이 아닙니다.

최종 크기 첫 프레임은 CPU 2스레드에서 약 100초였습니다. 72장의 직렬 렌더를 진행 중이며, 이 비용은 다른 장치의 성능 보장이 아닙니다. 전체 재생의 떨림·노이즈 깜박임·초점 전환 가독성, 인코딩 및 최종 파일 검사는 **아직 남아 있습니다**. 세 정지 이미지의 성공을 영상 완성으로 간주하지 않습니다.

## 재생성

Blender **4.3.2** 기준. 이 폴더를 저장소의 `second-cup-film/`에 놓으면 원본은 `../second-cup/The_Second_Cup.blend`에서 읽습니다. 로컬 실험용 형제 폴더 `second_cup/`도 지원하며, 다른 위치는 `--source`로 명시할 수 있습니다.

입력 원본 SHA-256:
`eac50adac6aa30158ea9cfac70d9d3c71ae25602abc33975fb0ec2023c9f49bd`

```sh
mkdir -p work/tmp
export TMPDIR="$PWD/work/tmp"

# 원본을 읽고 독립 애니메이션을 저장. 원본에는 쓰지 않음.
blender -b -t 2 --python-exit-code 1 --python rebuild_film.py
blender -b -t 2 --python-exit-code 1 --python audit_film.py

# 72장을 직렬 렌더. 중단 후 같은 명령으로 재개.
blender -b -t 2 --python-exit-code 1 --python render_frames.py
```

`rebuild_film.py -- --draft`는 같은 애니메이션을 만든 뒤 1·36·72프레임을 낮은 설정으로 `work/`에 렌더합니다. `--source /원본의/위치.blend`는 rebuild와 audit 양쪽에 같은 경로를 줍니다. 재생성은 **이 영화 폴더의 생성 결과**를 덮어쓰므로 진행 중 렌더와 동시에 재실행하지 않습니다.

| 소스 | 역할 |
| --- | --- |
| `rebuild_film.py` | 입력 SHA 검사, 카메라·초점 키프레임, 전체 프레임 여백 검사, 독립 `.blend` 생성 |
| `scene_fingerprint.py` | 카메라를 제외한 실제 사용 메시·재질·광원·world 비교 |
| `audit_film.py` | 저장된 파일 재개방, 원본 보존·애니메이션 채널·경로 검사 |
| `render_frames.py` | CPU 2스레드 직렬 렌더와 재개 가능한 완료 기록 |

렌더는 먼저 임시 PNG에 쓰고 CRC·768px 크기·압축 데이터 완결성을 검사한 뒤 프레임 이름으로 원자적으로 옮깁니다. `work/render_progress.json`의 완료 SHA와 파일이 일치할 때만 재개에서 건너뜁니다. 다른 `.blend`와 프레임이 섞이거나 완료 파일의 hash가 바뀌면 중단하며, 불확실한 파일을 조용히 재사용하지 않습니다.
