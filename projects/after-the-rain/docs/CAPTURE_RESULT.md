# 기존 캡처 저장 결과를 정확하게 기록하기

기존 F12 입력은 현재 뷰포트를 `res://preview.png`로 저장합니다. 이전 코드는 `Image.save_png()`의 반환값을 무시하여 저장에 실패해도 `Preview saved`를 출력했습니다. 이번 수정은 반환값이 `OK`일 때만 그 문구를 출력하고, 실패하면 `Preview not saved: …` 경고를 기록합니다. 화면 알림이나 새 저장 기능을 추가한 것이 아니라 실행 로그의 정확성을 고친 것입니다.

저장 경로·파일명·다음 캡처가 같은 파일을 덮어쓰는 동작·F12 입력 및 프레임 렌더 완료 대기는 그대로입니다. 자동 폴더 생성, 다른 위치로 재시도, 캡처 목록, 새 단축키는 없습니다. `res://`는 배포 환경에서 쓰기가 보장되지 않으므로 이번 변경이 모든 환경의 저장 성공을 보장하지 않습니다. [Godot 파일 경로 설명](https://docs.godotengine.org/en/4.6/tutorials/io/data_paths.html)과 [Image.save_png 반환값](https://docs.godotengine.org/en/4.6/classes/class_image.html#class-image-method-save-png)을 참고하세요.

## 검사 범위

- Godot 4.6.3, Compatibility/llvmpipe, 두 CPU 스레드와 Dummy 오디오로 별도 소스 사본을 실행했습니다. 실제 F12 키 입력으로 최초 저장, 같은 경로 덮어쓰기, 저장 실패, 장애 제거 후 재저장을 확인했습니다. 세 성공에서는 성공 로그가 각 한 번, 실패에서는 실패 경고만 추가됐습니다. 캡처 PNG는 각각 1180×663으로 디코딩됐고 두 번째 파일의 바이트가 첫 번째와 달랐습니다.
- 실패 조건은 사본에서 방금 만든 PNG를 별도로 보존한 뒤 `preview.png`라는 빈 디렉터리를 두어 만들었습니다. 저장 API가 `ERR_FILE_CANT_OPEN`을 반환했고 PNG 파일은 생기지 않았습니다. 이 검사는 읽기 전용 설치 위치나 디스크 부족을 실제 재현한 것은 아닙니다.
- 전체 자동 검사 54개 suite, 실패 0개. PCK 빌드 및 별도 위치에서의 의존성 검사 193파일, 실패 0개. 기존 간판 검사도 PCK에서 8개 통과했습니다. **실제 F12 검사는 소스 실행본에서 했으며 PCK에서의 캡처 저장 성공까지 검사한 것은 아닙니다.**
- 기존 가져오기 UID 대체 경고와 native VSync 미지원 경고가 있었고, 의도한 실패 시험에서는 PNG 저장 오류와 새 경고가 기록됐습니다. 모든 실행 로그가 무경고였다고 주장하지 않습니다. 최초 소형 API 재현 실행은 엔진의 기본 데이터 디렉터리를 만들지 못해 시작 중 종료됐으며, 별도 쓰기 가능한 실행 디렉터리를 지정한 후 재현했습니다.

다시 확인할 때는 반드시 폐기 가능한 프로젝트 사본과 그 사본에서 생성한 캡처만 사용하세요. F12는 기존 `preview.png`를 덮어씁니다. 첫 캡처를 보존하고 두 번째 캡처의 파일·로그를 확인한 다음, 그 사본에만 같은 이름의 빈 디렉터리를 두어 실패 문구가 성공 문구로 바뀌지 않는지 확인할 수 있습니다. 실패 조건을 제거한 뒤 다시 저장되는지도 확인하세요. 원래 프로젝트나 사용자의 기존 이미지로 시험하지 마세요.
