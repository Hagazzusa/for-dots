# 꽃집의 늦은 예약 수령

휴일 영업을 다시 시작하는 장면이 아닙니다. 첫 방문에서 포장 정리와 창가 인사 기회가 지나간 뒤에도 가까이 머물면, 예약 손님이 꽃다발을 받는 약 8초의 작은 장면이 이어집니다. 인사를 해야만 열리는 보상이나 퀘스트는 아닙니다. 보지 않고 버스로 떠나도 됩니다.

## 장면과 수명

- `scenes/flower_pickup.tscn`은 고객의 얇은 실루엣 5개 메시와 도착/대기/퇴장/보유 오프셋 마커를 저장합니다. 추가 조명, 충돌체, 내비게이션, 음성은 없습니다.
- `FlowerLife`는 기존 주인의 방문과 팔 표현을, 자식 `FlowerPickup`은 한 밤에 한 번의 수령 상태와 꽃다발 이동을 맡습니다. 타이머나 독립 업데이트 루프를 늘리지 않고 기존 Exploration의 delta만 받습니다.
- `reset_visit()`은 수령 완료를 지우지 않습니다. 새 밤의 `reset()`만 꽃다발과 고객을 초기화합니다. 수령 뒤 재방문에서는 포장을 다시 하지 않지만 기존 손인사 기회는 남습니다.
- 가까운 거리에서 실제 꽃집 쪽지가 열려 있으면 수령 **시작만** 미룹니다. 이미 시작한 수령은 읽기로 멈추지 않습니다. 다른 쪽지, 버스, 저녁 시계, 고양이는 영향을 받지 않습니다.
- 쪽지는 열 때의 상태에 따라 준비된 꽃, 찾아온 손님, 빈 물통을 구분합니다. 열려 있는 페이지는 장면이 진행되어도 갑자기 바뀌지 않습니다.
- 일시 정지는 기존 SceneTree 규칙을 따릅니다. 버스에 타면 Exploration 업데이트가 멈추며, 재시작은 중간 수령도 초기화합니다. 버스 시간과 탑승 조건은 수정하지 않았습니다.

## 표현의 범위

기존 꽃집과 같은 평면 실루엣 표현입니다. 주인의 소매 길이·방향을 조절해 포장지의 지정 접점을 따라가고, 손님이 받는 시점 이후에 주인의 손이 돌아옵니다. 해부학적 관절, 종이 물리, 실제 손가락 접촉을 재현하지 않습니다. 손님과 꽃다발은 퇴장 마지막 구간에서 함께 옅어집니다. 거리에서 걸어와 문을 여닫는 장면이 아니며, 창 안의 짧은 전달을 생략적으로 보여줍니다.

동작과 색상 자원은 인스턴스별로 분리하고 매번 저장된 기본 자세에서 계산합니다. 포장지와 손을 누적 이동하지 않습니다. 새로운 메시 5개가 보이는 동안의 비용이 추가되며, 프레임 속도 개선이나 모든 하드웨어의 성능을 주장하지 않습니다.

## 검증

Godot 4.6.3에서 다음을 확인했습니다.

- 전체 기존/신규 회귀 검사 49개 묶음, 실패 0개. 이 수치는 개별 assertion 수가 아니라 실행한 검사 묶음 수입니다.
- `tests/flower_pickup.gd`: 39개 검사. 첫 인사, 관련 글을 읽는 동안 시작 지연, 20회 재방문, 큰/잘못된 delta, 중간 새 밤, 인스턴스 분리와 복원을 포함합니다. 1/60초 표본에서 주인의 지정 접점, 손님의 보유 위치, 고객의 창 가로 폭, 동기화된 퇴장 투명도를 검사합니다. 연속 시간의 모든 시점이나 창의 전체 3D 충돌 안전을 증명하지 않습니다.
- `tests/flower_pickup_integration.gd`: 실제 Session, 입력 이벤트와 쪽지 대상, 수령 전후 글, 열린 글 유지, 시계/버스/고양이 진행, 비일시정지/일시정지/재개 양성 대조, 탑승과 새 밤을 확인합니다. 저장된 씬의 파일 저장·재개봉과 새 인스턴스도 검사합니다.
- 최종 런타임 PCK는 190파일로 빌드·격리 로드했고, 생산 입력과 의존성이 포함되며 테스트 도구/fixture는 포함되지 않았습니다. 도시 가져오기 자원의 UID를 찾지 못해 텍스트 경로로 대체하는 경고는 남았지만 의존성 로드 실패는 없었습니다.
- Compatibility/llvmpipe 네이티브 임시 실행에서 기본 시작점부터 방향키와 WASD로 꽃집 앞까지 이동했습니다. 인사 안내, 전달 중 양쪽 손과 꽃다발, 완료 뒤 빈 물통을 실제 진행의 여러 시점에서 확인했습니다. 그동안 버스가 정차 후 떠나 다음 도착 카운트로 이어졌고, Space와 R로 새 밤 복귀도 확인했습니다. 연속 영상 전체를 분석한 검증은 아닙니다.
- 별도 고정 자세 검사는 전달 중간과 퇴장 끝의 프레이밍을 확인하는 용도로 구분했습니다. 네이티브 로그에는 드라이버의 V-Sync 변경 미지원 경고가 있었으며, 오디오를 청취한 검증은 아닙니다.

재현: 프로젝트 루트에서 `bash tools/run_checks.sh`. 외부 QA 작업 디렉터리는 `RAIN_QA_ROOT`로 지정할 수 있습니다. 테스트와 패킹 도구는 생성 캐시·검증 파일을 기록하므로 원본 보존이 필요하면 별도 사본에서 실행하세요.

## 꽃집 앞면 접근 경계

기존에는 꽃집 옆의 불투명 벽을 보고 있어도 거리와 시선 조건만 맞으면 쪽지를 읽을 수 있었습니다. 수정 전 정상 키보드 보행으로 옆 보도에 접근해 이 동작을 재현했습니다.

`FlowerLife/FrontPlane`은 저장된 가게 외벽의 앞면과 일치하는 기준 마커입니다. 같은 앞면 판정이 꽃집 쪽지·손인사와 방문/수령 시작에 쓰입니다. 상호작용은 플레이어와 카메라가 모두 앞쪽에 있어야 하며, 기존 거리·시선 조건은 그대로입니다. 정면과 비스듬한 앞쪽 접근은 허용합니다. 고양이와 다른 장소의 읽기/좌석은 이 조건을 공유하지 않습니다.

이미 시작한 수령은 플레이어가 옆으로 가도 끝까지 진행하며, 완료 기록은 그대로 남습니다. 불완전한 첫 접근은 뒤로 가면 취소되고, 뒤쪽에서 열린 꽃집 글은 주인의 인사 시간을 붙잡지 않습니다. 전역 raycast나 임의 장애물에 대한 일반적인 가림 검사는 아니므로, 미래에 가게 앞에 새 벽을 추가하면 별도 검토가 필요합니다.

이 경계 수정의 최종 검증은 전체 50개 검사 묶음 실패 0개, `tests/flower_front.gd` 19개 검사 통과입니다. 기준면 양쪽과 정확한 경계, 사선 접근, 몸/카메라 불일치, 고양이 독립 대상, 수령 중 이탈과 새 밤 복원을 포함합니다. 최종 PCK 190파일도 격리 로드 검사 실패 0개이며, 앞서 적은 도시 UID 대체 경고는 그대로입니다.

수정 후보의 네이티브 정상 보행에서는 옆면에서 E를 눌러도 읽기가 열리지 않았고, 돌아서 앞쪽으로 이동한 뒤 같은 E 입력으로 쪽지가 열렸습니다. 임시 검증 창만 정상 종료했습니다. 이는 해당 가게와 실제 접근 경로의 검증이며, 모든 위치의 가림이나 다른 건물의 상호작용을 보장하지 않습니다.
