# 도시에서 강변으로 · 창밖 공간 연구

**게임 통합 보류.** 가까운 건물의 가림이 풀리면서 먼 다리가 드러나는 공간 전환은 실제 엔진 화면에서 관찰했다. 그러나 균일한 청색 수면과 작은 빛 표식만으로 자연스러운 강변이 충분히 읽힌다고 판단하지 않았다. 이는 제작자의 정성 관찰이며 독립 관찰자 검사나 인지 성공률 측정이 아니다.

[After the Rain](../after-the-rain/README.md)과 별개인 최소 Godot 프로젝트다. **24초/40m는 연구 씬의 값**이며 실제 게임 경로·시간표·시장길부터 강변까지의 거리·기존 8초 결말을 뜻하지 않는다. 기존 게임 코드·분기·시계를 사용하거나 변경하지 않는다. 강변 벡터 그림을 배경으로 붙이지 않았다.

## 구성과 한계

저장된 main.tscn 안에 3개 단순 가게, 강둑 난간, 먼 다리, 강 면, 창틀이 있다. World는 정지하고 RideRig만 X=0→40m로 이동한다. 기존 가게의 옆면이 지나가며 다리가 점차 드러나며 장면 교체나 연속 재생 중 순간이동은 없다. 고정 카메라는 rig-local (0,1.7,2), FOV67°다.

62개 BoxMesh 인스턴스(기하 기준 744삼각형), 8개 단순 재질이다. 추가 Light3D·이미지 텍스처·외부 모델·음성·충돌은 없다. 숫자는 저장 씬의 기하 구성이지 측정 draw call·FPS·실기기 성능 보장이 아니다. 엔진 기본 글꼴을 사용한다. 직접 작성한 코드와 원시 도형이며 새 포괄 라이선스를 부여하지 않는다.

물은 불투명한 양식화 색면이다. 12개 WaterMark는 수면 바로 위의 고정 3D 도형이며 물리 반사·굴절·수면 운동·화면 좌표 합성이 아니다. 원근에 따라 움직이지만 작은 수평선이라 강의 읽힘을 충분히 개선하지 못했다. 이 결과를 사실적인 물 표현의 성공으로 해석하지 않는다.

## 실행·재현

Godot 4.6.3 Standard / Compatibility에서 실행했다. Python 생성기는 표준 라이브러리만 사용한다.

```sh
godot --path . --rendering-method gl_compatibility
# 최종 저장 씬을 다시 생성: main.tscn을 덮어쓴다.
python3 build_scene.py
# 저장 씬/상태의 작은 headless 검사
godot --headless --path . --script res://test_study.gd
```

Space 재생/정지, R 초기화, 1/2/3 검토 위치, Escape 실험 종료. 1/2/3은 정지 화면 비교용 직접 이동이며 정상 연속 재생과 구분한다. 24초에 위치가 끝점에 고정되지만 PLAY 표시는 재생 선택 상태를 나타낸다. Godot 실행은 .godot 캐시를 생성할 수 있다. 생성기나 검사기는 게임 파일을 읽거나 쓰지 않는다.

## 보존한 비교

- `variants/initial.tscn`: 어두운 수면·높은 난간의 첫 비교. 최종과 동일한 카메라·창·이동 스크립트다.
- `variants/contrast.tscn`: 수면 색/범위/높이·하늘 대비·난간 높이를 함께 바꾼 중간안. 수면 상승으로 표식이 가려졌다. 단일 변수 실험이 아니다.
- `main.tscn`: 중간안에서 12개 표식의 Y만 −.375→−.075로 복구. 수면 상단 −.09, 표식 밑면 −.0875다. X/Z·크기·재질·빛·카메라·시간은 불변이다.

각 변형은 Godot에서 해당 tscn을 실행하면 볼 수 있다. build_scene.py는 최종안만 생성하며 비교 씬을 덮어쓰지 않는다.

1180×812 실제 앱 화면을 그대로 보존했다. 고정 마지막 시점 비교는 3번 검토 키로 정지한 화면이다. 연속 전환은 별도로 24초 전체를 관찰했으며 최종안 140회 캡처 표본의 수집 시간은 26.045초였다. 이는 140fps·영상 프레임 정확도·모든 순간의 검사라는 뜻이 아니다. 대량 연속 캡처 대신 시작/전환 두 표본만 포함했다. JPEG는 원본 캡처 바이트 그대로이며 확대·크롭으로 판독 성공을 주장하지 않는다.

소프트웨어 llvmpipe / CPU 스레드 제한2 / Dummy 오디오 조건이었다. 새 창의 실행·종료와 초기화는 확인했지만 모든 해상도·GPU·장시간 실행·배포 PCK는 검사하지 않았다. native 로그에는 VSync 변경 미지원 경고가 있었다. headless editor에는 편집기 설정 저장 경고가 있어 이를 완전 무경고 import로 주장하지 않는다. 최종 headless 검사는 별도 기록이며 native 판독을 대체하지 않는다.

공개 사본의 세 저장 씬을 새 headless 실행에서 읽어 시작/중간/일시정지/큰 delta 끝점/초기화 핸들러/메시 수 18항목을 검사했다. 직접 메서드 호출 검사이며 실제 키 전달·SceneTree pause·GPU 렌더 검사가 아니다. 이전 검사 실행에는 Fontconfig 캐시 쓰기 경고가 있었고, 캐시 경로를 지정한 최종 재실행은 경고 없이 18항목 통과했다. 이는 headless editor import 전체가 무경고였다는 뜻은 아니다.
