# 실제 확인한 재현 범위

## 실행한 검사

1. Blender 4.3.2 / Cycles CPU 두 스레드로 1100 × 900, 64 samples 최종 이미지를
   실제 생성하고 화면 전체를 확인했습니다.
2. 공개 준비 과정에서 코드를 다른 폴더로 복사하고, 그 폴더 바깥을 현재
   작업 디렉터리로 삼아 `--preview`를 실행했습니다. 640 × 520 이미지,
   새 blend, 검증 JSON이 코드 옆에 생성되었습니다. 외부 이미지 참조는 0개였습니다.
3. 공개용 blend를 다시 열어 물체 101개, 1100 × 900 설정, 상대 렌더 경로,
   외부 이미지·링크 라이브러리 없음, 내장 글꼴만 사용함을 확인했습니다.
4. 메타데이터 정리 전후의 물체 이름·종류·변환 행렬·메시 정점·면 배열을
   정렬해 해시를 비교했습니다. 형상 정보가 동일했습니다. 결과는
   `publication_qa.json`에 보관했습니다.
5. 최종 PNG는 완전히 불투명하며 크기는 1100 × 900입니다. 아래 25줄의
   최소 평균 RGB는 48.50/255로, 앞서 발견한 검은 띠가 사라졌습니다.
6. PNG에는 DPI 정보만 남아 있고 경로·시간·EXIF 텍스트는 없습니다. 배포 blend와
   새로 재생성한 blend의 바이트에서 알려진 작업공간·홈 디렉터리 접두어를
   검색해 남은 항목이 없음을 확인했습니다. 파일 브라우저의 문자열 뒤 잔여
   바이트도 정리했고, 비어 있는 시퀀서의 이전 이미지 폴더 기록도 제거했습니다.

## 범위와 한계

- 다른 폴더에서의 재생성 시험은 작은 preview로 실행했습니다. 공개 준비 단계에서
  전체 크기 이미지를 한 번 더 렌더하지는 않았습니다. 최종 이미지는 앞서 실제
  렌더한 픽셀을 그대로 보존했고, 이후 코드 수정은 저장 전 파일 브라우저·빈 시퀀서의 UI 경로 기록과
  PNG의 불필요한 위치 메타데이터를 비우는 처리뿐입니다.
- 형상 해시는 장면의 모든 의미나 모든 렌더 픽셀을 증명하는 검사는 아닙니다.
  최종 화면의 물체 형태·가림·구도는 별도로 시각 검토했습니다.
- Blender 4.3.2 한 환경에서 검사했습니다. 다른 버전·운영체제에서의 동작이나
  픽셀 단위 동일성은 보장하지 않습니다. 실행 시간의 성능 보장도 없습니다.
- 공개 파일에 대한 위 검사는 한정된 항목을 확인한 것입니다. 일반적인 보안
  감사·실물 제작 검증·정확한 광학 또는 건축 분석을 뜻하지 않습니다.
