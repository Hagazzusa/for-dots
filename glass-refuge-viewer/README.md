# Glass Refuge — 상호작용형 건축 연구

실제 편집 가능한 Glass Refuge 모델을 보여 주는 작은 독립형 Godot 4.6 뷰어입니다. 독창적인 **GPT Image 콘셉트 → Blender 모델 → 실시간 상호작용** 실험의 다음 단계입니다. 게임 확장, 이미지 빌보드, 실제 건물의 재구성, 시공 문서가 아닙니다.

## 열기와 조작

Godot **4.6.3** 또는 호환되는 4.6 버전에서 `project.godot`를 열고 메인 장면을 실행하세요. 다음 명령도 사용할 수 있습니다.

```sh
godot --path /path/to/glass_refuge_viewer --audio-driver Dummy
```

- **방향키:** 수평으로 회전하거나 시점을 올리고 내립니다.
- **+ / = 및 −:** 제한 범위 안에서 확대/축소합니다.
- **L:** 실제 펜던트 조명과 구체의 발광을 켜고 끕니다.
- **G:** 구조 검사를 위해 유리를 숨기거나 표시합니다.
- **R:** 카메라, 조명, 유리를 초기화합니다.
- 선택적으로 왼쪽 드래그/휠로 회전과 확대/축소가 가능합니다. 마우스 캡처는 필요하지 않습니다.
- 조작 버튼을 클릭해도 방향키 탐색 포커스를 빼앗지 않습니다. 창이 포커스를 잃으면 드래그 상태를 해제합니다. 걷기 모드는 없습니다.

## 실제 포함 내용

`assets/refuge.glb`에는 **삼각형 78,388개, 메시 노드 33개, 재질 표면 35개, 재질 정의 10개**가 있습니다. 소스에서 추정하지 않고 실제 내보낸 GLB에서 측정했습니다. 크기는 3,617,000바이트입니다. 곡선 골조, 구리 덮개와 부속, 유리판 24개, 세이지색 판재, 벤치/쿠션/담요, 빈 화분 상자, 펜던트 기구, 석재 테라스/진입부를 포함합니다. 선택한 원본 메시 오브젝트 316개를 파생 작업으로 변환해 노드 33개로 병합했습니다. 병합 전후 경계는 0.00001 Blender 단위 이내로 일치합니다. 치수는 해석에 따른 설계 선택이며 실측값이 아닙니다.

다운로드한 에셋, 텍스처 맵, 무거운 베이크, 외부 플러그인은 없습니다. 원본 Blender 장면과 최종 Cycles 렌더는 변경하지 않았습니다. 기존 After-the-Rain 프로젝트를 참조하거나 변경하지 않습니다.

## 시각적 차이

- 원본의 절차적 나뭇결, 구리 변화, 천 직조, 젖은 돌 범프, 물방울 미세 디테일을 대략적인 상수 PBR 색상/거칠기로 대체했습니다. **Cycles와 같은 시각적 결과가 아닙니다.**
- 모든 식물 메시와 먼 풍경을 제외했습니다. 화분 상자는 의도적으로 비워 두었습니다.
- 유리는 물리적 투과/굴절 대신 절제된 알파 블렌딩을 사용합니다. 겹친 투명 표면에서 정렬 차이가 보일 수 있으며 G 전환으로 구조를 명확히 확인할 수 있습니다.
- Cycles 면광원 세 개와 절차적 월드는 옮겨지지 않습니다. 대신 저장된 황혼 환경, 방향광 하나, 동적 펜던트 OmniLight를 사용합니다. 간접광 베이크를 주장하지 않습니다.
- 원본의 명목 치수, 유리 안전성, 지지, 배수, 접근성, 건축 법규 준수는 검증하지 않았습니다.

## 저장된 장면 구조

- `scenes/viewer.tscn` / `scripts/viewer.gd`: 눈에 보이는 구성 루트, 환경/UI, 명시적인 자식 연결.
- `scenes/refuge.tscn` / `scripts/refuge.gd`: 가져온 파생 지오메트리와 인스턴스별 유리 상태.
- `scenes/view_rig.tscn` / `scripts/view_rig.gd`: 카메라 회전/확대·축소/초기화만 담당.
- `scenes/pendant.tscn` / `scripts/pendant.gd`: 조명 상태를 소유하며 루트에서 원본 구체 메시를 명시적으로 전달받음.

오토로드, 전역 게임 상태 관리자, 숨겨진 생성 월드 대체물, 물리 컨트롤러, 원본 `.blend` 변경은 없습니다. GLB 계층은 편집기에서 검사할 수 있습니다. 런타임 재질 재정의는 의도적이며 각 인스턴스에 국한됩니다. 테스트는 한 뷰어가 다른 뷰어의 상태를 바꾸지 않는지 검사합니다.

## 파생 결과 재현

런타임은 독립적으로 동작합니다. GLB를 다시 만들려면 Blender 4.3.2와 별도 보존한 원본 `.blend`가 추가로 필요합니다.

```sh
blender -b -t 2 --python tools/export_refuge.py -- --source /path/to/Glass_Refuge.blend
godot --headless --path . --editor --import
godot --headless --path . --script res://tools/test_viewer.gd
```

소스 인자나 이미 열린 Blender 파일이 없으면 내보내기 도구는 공개된 이웃 파일 `../glass-refuge/Glass_Refuge.blend`를 찾습니다(저장소 폴더명은 하이픈 사용). 독립 실행 런타임에는 이 파일이 필요하지 않습니다. 내보내기 스크립트는 소스를 메모리에서 읽고 모디파이어를 평가하며, 메모리 안의 파생 사본에서만 재질을 교체합니다. 정적 불투명 그룹을 병합하고 유리판/구체는 분리 보존한 뒤 GLB를 내보냅니다. 원본 Blender 파일을 저장하지 않으며 전후 소스 SHA-256을 검사합니다. 기록된 소스 해시는 `qa/export_audit.json`에 있습니다.

## 검증과 한계

- 실제 GLB 토폴로지/재질 개수: `qa/glb_audit.json`.
- 소스 해시 보존과 병합 전후 경계: `qa/export_audit.json`.
- 헤드리스 로직: 완전한 한 바퀴 회전, 확대·축소/상하 각도 제한, 조명/유리/초기화 키 처리, 키 반복 억제, 반복 전환, 독립 인스턴스, 해제 후 재생성을 포함해 **검사 42개 통과**. `qa/headless_tests.json`.
- 별도 네이티브 창 검사 통과: 실제 정면/측면/후면 픽셀과 완전한 회전, 방향키 수직 탐색, 확대·축소, 초기화, 눈에 띄게 다른 조명 켜짐/꺼짐, 유리 가시성, UI 버튼 클릭 후 키보드 탐색을 확인했습니다. 최종 상태는 기본 전면 사선 시점이며 조명과 유리가 켜져 있습니다. `physical_keycode == 0`인 논리 키 이벤트를 지원하고 시험했습니다.
- 원격의 누름 시간 0인 문자 키 입력은 불안정했으나, 의도적인 200–250 ms 누름은 일관되게 동작했습니다. 모든 원격 입력 타이밍이 안정적이었다고 주장하지 않고 이를 기록합니다.
- 관찰한 네이티브 렌더러: Mesa llvmpipe / OpenGL Compatibility. FPS는 측정하지 않았습니다. 환경 경고는 V-Sync 전환 미지원과 오디오 기기 없음을 보고했습니다. 무음 뷰어는 더미 오디오로 대체하며, 위 실행 명령은 Dummy 오디오를 명시적으로 선택합니다.
- 공개 파일 25개만 포함한 새 사본은 기존 `.godot` 캐시 없이 성공적으로 가져왔고 같은 헤드리스 검사 42개를 통과했습니다. 실행에 이웃 소스 blend는 필요하지 않습니다.
- 렌더러: Compatibility. 자동 인스턴싱 성능, 베이크된 GI, 대상 기기의 FPS는 보장하지 않습니다.

### 소스 출처 참고

기록된 소스 SHA-256은 이 파생 작업에 사용한 원래 작업용 Blender 파일을 식별합니다. 별도로 공개한 `glass-refuge/Glass_Refuge.blend`는 공개 과정에서 지오메트리나 내장 참조 픽셀을 바꾸지 않고 절대 편집기/이미지 경로를 제거하므로 파일 해시가 다를 수 있습니다. 정규화한 공개 이웃 파일에서 다시 내보내면 그 입력의 해시를 기록합니다. 컨테이너 메타데이터 해시 차이가 지오메트리 변경을 뜻하지는 않습니다.
