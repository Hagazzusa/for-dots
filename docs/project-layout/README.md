# 프로젝트 통합과 중복 정리 · 2026-11-05

모든 65개 작품·게임·연구의 정식 경로를 `projects/<kebab-case>/`로 통합했습니다. 저장소 루트에는 프로젝트를 개별 배치하지 않으며, 공통 설명·갤러리·검증기와 `docs/`, `tools/`, `projects/`만 둡니다. 한 프로젝트의 여러 매체는 같은 폴더에서 관리합니다.

[현재 프로젝트 목록](../../projects/README.md) · [작업 지침](../../AGENTS.md) · [이관 직전 버전](https://github.com/Hagazzusa/for-dots/tree/01938507b3f00779dc13f404d1f6d32337f0b02d)

## 중복과 버전 비교

- 기존 최상위 프로젝트 48개를 `projects/`로 옮겼습니다. 앞서 정리한 17개와 합쳐 정식 프로젝트는 65개입니다.
- 날짜 보관본의 프로젝트 파일 174개 모두 정식 경로에 대응했습니다. 140개는 바이트가 같았고, 34개는 문서·매니페스트·형제 경로 코드의 이전 버전이었습니다. 정식 경로에 없는 고유 작품 파일은 없었습니다.
- 현재 정식본을 유지하고 중복 날짜 폴더와 그 보관용 목록을 제거했습니다. 이전 문서와 코드, 당시의 매니페스트는 위 Git 커밋에서 확인할 수 있습니다. 이력은 다시 쓰지 않습니다.
- 같은 프로젝트의 호환성용 복사본은 남기지 않았습니다. 기존 파일 링크는 새 경로로 바뀝니다. 프로젝트 내부에서 실제 실행에 필요한 자원이나 외부 에셋·라이선스를 임의로 중복 제거하지는 않았습니다.

## 경로와 문서

루트 README·갤러리·세계 연결 안내, 65개 프로젝트 색인, 관련 문서·메타데이터 경로와 AGENTS 지침을 갱신했습니다. 그림책의 PDF 생성기와 오프라인 패키징 도구는 저장소 루트의 `--repo .`에서 `projects/`를 찾으며, 독립 패키지에서도 기존처럼 작동합니다.

변경한 문서·코드·출처 경로를 포함하는 프로젝트 매니페스트를 갱신했습니다. 역사적 검사 기록이나 과거에 대체된 파일명은 당시 사실을 설명하는 경우 보존했습니다. 현재 추적 파일 전체의 크기와 SHA-256은 루트 `SOURCE_MANIFEST.json`이 기준입니다.

## 확인한 것

- 중복 보관본을 제외한 모든 기존 추적 파일이 새 경로에 존재하는지 비교했습니다. 고유 파일 누락은 없습니다.
- 이미지·영상·음원·PDF·편집 모델 등 작품 결과물은 원본 바이트 그대로 이동했습니다. 외부 에셋·라이선스와 사용자 문구는 무관하게 변경하지 않았습니다.
- 저장소 Markdown의 상대 링크 500개가 실제 파일·디렉터리를 가리키는지 확인했습니다.
- Python 187개와 셸 스크립트 7개의 구문 검사, 공통 도구 테스트 48개를 통과했습니다.
- 그림책의 정식 경로·새 오프라인 패키지·독립 패키지 재포장 세 경우에 탐색 검사와 이미지 경로 검사를 통과했습니다. 패키지의 PNG는 원본과 바이트가 같습니다.
- 저장소 루트 `--repo .`로 그림책 PDF를 별도 폴더에 다시 만들었고 3쪽 출력이 성공했습니다. 저장된 작품 PDF는 덮어쓰지 않았습니다.
- 게임의 결정적 라디오 PCM 생성 검사를 통과했습니다. 게임 코드·씬·에셋은 변경하지 않았습니다.

## 실행하지 못한 검사

게임 전체 회귀검사는 Godot 4.6.3의 새 가져오기 단계에서 프로세스가 exit 137로 종료돼 테스트 본문까지 진행하지 못했습니다. 별도 작업 사본에서 작업 스레드와 CPU 실행 범위를 제한해도 같았습니다. 따라서 이번 전체 게임 회귀검사가 통과했다고 주장하지 않습니다. 가져오기 실패의 정확한 원인까지 확인한 것은 아닙니다.

도시 에셋 재조립 스크립트에는 공개본에 없는 외부 `city_asset_sources`가 필요합니다. 기존 의존성이며 이번 이동으로 생긴 문제는 아닙니다. 공개된 실행 에셋은 그대로 보존했습니다. 전체 3D 재렌더나 모든 프로젝트의 시각·청취 재평가는 이번 경로 정리의 검사에 포함하지 않았습니다.

## 다시 검사하기

저장소 루트에서 `python3 verify_sources.py`로 현재 전체 파일 해시를 검사합니다. 기능별 재현은 각 프로젝트의 README를 따릅니다. 생성기가 원본을 덮어쓸 수 있으므로 재생성 시험은 별도 사본에서 수행하세요.
