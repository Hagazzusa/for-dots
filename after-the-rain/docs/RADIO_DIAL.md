# 라디오 전원 표시창 재구축

재구축 기준본의 라디오 주파수 창(Tuner)은 황토색 고정 재질이었고 전원 상태에 연결되지 않았다. 이번 변경은 유실 전 버전에서 설명했던 다이얼 불빛을 **현재 재구축본에서 다시 구현한 것**이다. 사라진 소스나 과거 검사 결과를 복구했다는 뜻은 아니다.

기존 라디오를 바라보고 E를 누르면 작은 창이 따뜻한 호박색으로 밝아지고, 다시 누르면 원래 재질로 돌아간다. E 안내도 현재 가능한 ‘켜기’ 또는 ‘끄기’를 표시한다. 음소거는 전원을 끄는 행동이 아니므로 창은 켜진 채 남는다. 새 밤, 버스 탑승과 앱 종료 준비에서는 꺼진다. 새로운 이야기 창이나 입력·버스 시간 변경은 없다.

## 장면 책임

- `small_radio.tscn`의 기존 Tuner 면과 `radio_dial.gd`가 표시를 담당한다. 켜진 재질은 Inspector에서 읽을 수 있는 `radio_dial_lit.tres`다. 장면의 exported 참조에도 이 외부 재질을 명시적으로 저장한다. `@tool` 미리보기 기능은 아니다.
- 오디오 소유자 `story_radio.gd`가 전원 변경 신호를 내고, 공통 소유자 StoryCorner가 표시 장면에 연결한다. 재생 시간이나 별도 타이머로 불빛을 추정하지 않는다.
- 두 상태의 재질을 인스턴스마다 한 번 복제해 재사용한다. 현재 재질에는 텍스처 등 하위 Resource가 없으며, 향후 하위 Resource를 넣으면 얕은 복제의 공유 범위를 다시 검사해야 한다. null 설정은 원래 꺼진 재질로 대체한다.
- 기존 면의 emission만 사용한다. 새 mesh·텍스처·Light3D나 bloom은 추가하지 않는다. 주변을 실제로 비추는 광원이나 물리적인 전구 시뮬레이션은 아니다. GPU/FPS 개선을 측정하지 않았다.

## 검증

첫 PCK 검사에서는 스크립트 preload만으로 새 재질이 의존성 목록에 포함되지 않아 로드 오류가 발생했다. 저장된 장면에 외부 Material 참조를 명시하고, 이 경로가 실제 의존성 목록에 있는지 회귀 검사를 추가했다. 원본 게임의 전체 패커를 변경하지 않았다.

- 최종 소스 전체 53개 검사 suite가 통과했다. 독립 PCK 193파일의 의존성/테스트 제외 감사와 동일 전용 24항목도 통과했다. 첫 PCK의 재질 누락은 재실행에서 해소됐으며, 기존 도시 에셋의 UID 대신 텍스트 경로를 사용하는 경고는 남아 있어 무경고 실행이라고 주장하지 않는다.
- Godot 4.6.3 Compatibility의 `tests/radio_dial.gd`는 두 인스턴스의 재질 격리, 원본 불변·캐시 재사용, 초기/준비 전 주입/null 상태, mute/pause, reset/leave/shutdown과 실제 Session E/M/R 입력을 검사한다.
- 실제 1180×812 창에서 라디오 앞 약 1.4m의 고정 시점으로 비교했다. 첫 밝기는 색 변화가 미묘해 보류했고, 같은 면·카메라에서 emission 색과 강도만 조정한 두 번째 후보를 선택했다. 최종 값은 emission `(0.8, 0.38, 0.09)`, 강도 `1.2`다. 정상 크기에서 전원 표시창을 구분했으며 더 큰 광원이나 화면 효과로 확대하지 않았다.
- 실제 UI에서 E 전환과 음소거·일시 정지 복귀를 확인했다. 시작 위치를 정한 별도 검사 장면을 사용했으며 정상 시작점부터 걷는 전 경로 검사는 아니다. 모든 거리·해상도나 독립 관찰자의 인지율을 검증한 것은 아니다.
- 네이티브는 llvmpipe, Dummy 오디오를 사용했다. V-Sync 미지원 경고가 있었으며 직접 청취나 하드웨어 GPU 성능 검사는 하지 않았다.

재실행: `godot --headless --path . --script res://tests/radio_dial.gd` 또는 `bash tools/run_checks.sh`. 엔진 가져오기 캐시와 검사 로그가 생성될 수 있다.
